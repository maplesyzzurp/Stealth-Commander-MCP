Setup guidance and issue reporting for Stealth Commander by Nexusmap.ai. Start with the connection and the tools your paired Windows client actually provides.

Access remains invite-only. Signing in requires an approved account. A public issue report does not approve an account, pair a PC, or grant remote access.

Start here.

I cannot connect or see my PC.

Confirm that you are using an approved account, the Windows client is running, and local pairing and remote setup are complete. Use your host’s connection flow to sign in through OAuth and select the intended paired PC. The device must stay online.

If access has expired or was revoked, reconnect through the supported sign-in flow. Do not share account keys or substitute a direct tunnel URL.

A tool or application workflow is unavailable.

Ask for a readiness report and check the tools exposed by the connected PC. The installed client determines available capabilities; updating the chat plugin does not update that client. Browser and IDE workflows also need their own application dependencies.

Report the actual missing capability or returned error. Do not assume a launch tool provides arbitrary clicking or typing in every application.

An observation is missing or stale.

Check the owned session’s observation status and capture timestamp. Cached-image export reads an already-published frame; it does not start an observer or request a new screenshot. An unavailable, expired, protected, or mismatched frame should remain an explicit error.

A command or session operation timed out.

A timeout may leave the result uncertain. Inspect the exact owned session or task state before retrying an operation that could change something. Keep the original session identity and stop only that session when its task is complete.

Can it operate my current desktop or record audio?

The supported workflow uses owned hidden sessions and preserves shared foreground input. It does not provide arbitrary full-desktop video or system-audio recording. See the operating scope before starting a task.

Report a reproducible issue.

The project’s established issue-reporting channel is GitHub Issues. Reports are public; posting may require a GitHub account.

  • The task you attempted and what you expected to happen.
  • The client or plugin version and relevant Windows/application versions.
  • Minimal reproduction steps using neutral sample data.
  • The actual error, with sensitive details removed.
View or report an issue

Keep private information out of public reports.

Never post passwords, account keys, OAuth tokens, connection or tunnel URLs, sign-in logs, personal file paths, or screenshots containing private data. Review and redact every attachment. Do not use a public issue to send account-access details or sensitive security information.

Share the smallest useful example.

A short description and sanitized error often provide more useful evidence than a full log or desktop capture. Replace personal project data with a neutral sample, and include only the details needed to reproduce the problem.

These pages provide product information and public issue guidance. Account approval, pairing, and device consent remain part of the protected sign-in and local setup workflows.
