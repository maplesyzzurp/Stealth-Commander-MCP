Stealth Commander connects a Windows computer you own or administer to a compatible MCP client. Check readiness, inspect hidden sessions, run authorized commands, and view supported observations on the PC you select.

Create account Sign in

Account creation is open. The Windows client is currently distributed privately, and the ChatGPT plugin is not publicly listed. Creating an account does not install the client or pair a PC.

Work with the PC you choose.

The installed Windows client determines which tools are available. The connection acts on the paired device selected during consent.

01 / CHECK

See what is ready

Check runtime and application prerequisites, discover available tools, and inspect the status of owned hidden desktop sessions.

02 / RUN

Carry out a defined task

Run bounded commands with the selected Windows account’s permissions. Supported launch tools create separate, owned application sessions.

03 / OBSERVE

View session observations

Review session status and cached window images. Images include their capture time and session identity.

Start with a paired Windows client.

The chat plugin connects to your client; it does not install the Windows runtime.

  • A Windows x64 PC you own or are authorized to administer.
  • Python 3.11 or later, a privately supplied Stealth Commander Windows client, and the dependencies for your intended workflow.
  • A Stealth Commander account and a paired PC that remains online.
  • A compatible host with OAuth support for the remote MCP connection.
  1. Install and pair locally

    Use your privately supplied Windows client and its local setup flow. Complete account sign-in and explicitly enable remote access on the PC.

  2. Connect through your host

    Start the Stealth Commander connection, sign in through OAuth, and choose the paired PC you want to authorize.

  3. Check before you run

    Ask for a readiness report and inspect the tools the connected PC actually exposes. Additional browser or IDE workflows have their own prerequisites.

What hidden sessions can do

Owned hidden sessions keep their GUI input separate from your normal desktop. They do not sandbox the Windows account’s filesystem or network access. Commands still use that account’s permissions.

The supported workflow preserves your physical mouse, keyboard, personal browser profile, and existing IDE sessions. Cached observations are already-published frames; they are not a full-desktop video or system-audio recording.

Some browser and native-desktop capture workflows remain under testing. A successful connection or readiness check does not establish that every application can be controlled or captured.
